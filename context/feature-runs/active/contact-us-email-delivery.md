## Migration and outbox audit

The dev database could not run this feature at all: the `OutboxEvent` table was
missing, so every contact submission failed and the outbox poll crashed the API
process. A full audit of the migration history found the underlying cause.

- `prisma migrate status` was lying. Against the pooled Neon endpoint
  (`-pooler`, `pgbouncer=true`) the migration engine reads an empty
  `_prisma_migrations` table and reports every migration as unapplied, exit 1.
  Over the direct endpoint the same command reports "Database schema is up to
  date". Prisma Client on the pooled URL reads the ledger correctly, so this is
  specific to the migration engine.
- That false reading explains the corrupt ledger: four rows carry
  `applied_steps_count = 0`, the signature of `migrate resolve --applied`, and
  two of them (`20260717120000_add_cpe_credit_type`, `20260717120100_cpd_plans`)
  are ghosts whose SQL never ran and whose renamed successors did.
- Three applied migrations had checksum mismatches, i.e. their files were edited
  after being applied. None left schema drift.
- Fix: the datasource now declares `directUrl`, wired through `.env.example`,
  CI, and both e2e setup files with a fallback to `DATABASE_URL`.

Applying the two pending migrations was verified before execution by rehearsing
`migrate deploy` on a byte-faithful local clone (schema plus all 14 ledger rows
dumped from Neon). The clone's before/after schema diff showed only the outbox
objects added and nothing removed; the live database produced the identical
result. `20260712000000_restore_historical_baseline` is a no-op there because its
entire body sits behind `IF to_regclass('"PDUTarget"') IS NULL`.

Outbox defects found and fixed, each with a regression test:

- The poll callback let rejections escape, so a failing claim query terminated
  the API. Ticks are now wrapped and logged.
- `setInterval` started overlapping ticks, which is how one inquiry produced two
  claims and two provider sends.
- A concurrent delivery insert surfaced as a unique-constraint failure and was
  recorded as a failed attempt, rescheduling an event that had already been
  delivered.
- Events hitting the attempt ceiling were abandoned silently; that now logs.

## Notes

- `Public` decorator moved to `@common/decorators/public.decorator` (platform-shared)
  with a re-export left at `@auth/decorators/public.decorator`. This is the fix
  EXC-034 through EXC-038 already name, and it let the new public mutation ship
  without adding a twelfth boundary exception to a register the roadmap requires
  to shrink. Existing callers and their fingerprints are untouched.
- New bounded context `public-support` owns the `support` module; it depends on
  `communications` and `platform-shared` and owns no Prisma models.
- `tsconfig.build.json` restates the alias map rather than inheriting it, so a
  missing `@support/*` there passed lint, types, and tests but failed
  `nest build`. `alias-resolution.spec.ts` now compares the two maps.
