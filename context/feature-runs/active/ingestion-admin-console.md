## Notes

- Model tier: **High reasoning**, per `context/model-selection.md`. This run
  adds a Prisma migration, an authorization-gated GraphQL contract, and a
  concurrency-sensitive approve/reject transaction — three of the tier's own
  named triggers.
- Requirement 11 (a rejected item re-crawled unchanged stays rejected; re-crawled
  changed returns to the queue) is already satisfied by the unmodified phase-03
  `persistAccepted` code: the hash-and-diff short-circuit never touches `state`
  on an unchanged re-submission, and a changed re-submission unconditionally
  resets `state` from the source's `autoPublish` flag. No phase-03 file changes;
  this run adds an e2e test that proves it end-to-end through the admin reject
  mutation and the real ingestion pipeline.
- Field map validation on create/update reuses phase 03's `validateCourseFieldMap`
  verbatim when `kind === COURSE`. For the other three kinds — schema-legal but
  not yet ingestable (phase 05) — any non-empty field map is rejected, since no
  canonical field list exists yet to validate a "rename and pick" map against.
- Approve/reject use a read-then-conditional-`updateMany`-on-the-observed-state
  pattern, matching "Concurrency and race conditions" in the coding standards.
  The item state change, the catalog publish/unpublish, and the outbox append
  share one transaction.
- Two new read-only admin methods (`getBatchForAdmin`, `listBatchesForSource`)
  were added to the existing `CourseIngestionService` rather than a new service,
  because they reuse its private report-parsing/counting helpers
  (`toStoredReceipt`) — duplicating that logic elsewhere risked drift from the
  REST path's counts.
- Two real bugs were found and fixed via browser testing, after the gates
  above had already passed once:
  - An i18n interpolation bug: `keys.revokeDialog.description` used the
    single-brace `{prefix}` placeholder, but `language-provider.tsx`'s actual
    implementation only replaces `{{prefix}}` (double braces). Fixed in both
    `en.json` and `fr.json`. (A pre-existing, unrelated instance of the same
    single-brace mistake in `adminDashboard.associations.create.sentBody` was
    left untouched as out of scope.)
  - A narrow-viewport layout bug: `admin-ingestion-source-detail.tsx` placed
    the deactivate/activate button directly as a `flex-col` child with no
    wrapping element, so it inherited `align-items: stretch` and rendered as a
    full-width bar at 375px. Fixed by wrapping it in `<div className="flex
    flex-wrap gap-2">`, matching the header pattern already used in
    `AdminAssociationsTab.tsx`.
  Both fixes are frontend-only; the frontend gate (lint, check-types, build)
  was re-run afterward and is clean (see Verification).
- Two further apparent issues were investigated during browser testing and
  confirmed to be false alarms, not defects — no code was changed for either:
  - A transient run where the API-keys table appeared to show only one of two
    issued keys. A direct GraphQL query confirmed the server was returning
    both correctly, and two clean reruns of the identical issue/revoke/issue
    sequence both showed the correct two rows immediately. Concluded to be
    dev-server response lag under concurrent Playwright load, not an
    application defect.
  - The review queue's empty state appeared blank at 375px. The empty-state
    icon and message were confirmed present in the DOM via `innerHTML`, and
    the table's own `overflow-x-auto` container was confirmed to be the
    thing scrolling (to ~1000px) while the page body correctly stayed at
    375px — exactly the coding standard's "the table scrolls, not the page"
    requirement. Scrolling the container brought the message into view.
- The local dev `.env` (gitignored) was missing `http://localhost:3000` from
  `CORS_ORIGIN`, which blocks credentialed cross-origin calls from the
  frontend dev server to the API dev server. Fixed locally to unblock browser
  testing; not part of this branch's diff.
