# Modular monolith final review

## Decision

The modular monolith remains the appropriate deployment architecture. Domain
ownership, public application contracts, transaction boundaries, reliable
side effects, storage, and operational probes are explicit. Extracting an
independent worker is now mechanical, while extracting a domain service still
requires the measured decision gate in `monolith-hardening.md`.

## Before and after

| Measure | Baseline | Final |
| --- | ---: | ---: |
| Bounded contexts | implicit | 9 declared |
| Prisma models with one owner | unverified | 100% enforced |
| Temporary boundary exceptions | 45 identified | 0 temporary; 11 explicitly retained compatibility edges |
| Versioned durable side effects | 0 | mail and audit reactions |
| Storage-backed evidence consumers | filesystem-coupled | 3 behind one port |
| Operational probes | 0 | liveness + database readiness |

The remaining registered compatibility edges are explicitly retained; the
cross-domain reads among them are treated as read-only projections where the ownership manifest permits them. The
dependency graph test remains the source of truth for acyclicity. The mail to
auth cycle was removed in this phase; no new cyclic edge was introduced.

## Reliability review

Outbox rows are written atomically, claimed safely under concurrency, retried
with a bounded policy, and retained for inspection. Handler receipts prevent a
duplicate claim from repeating a completed side effect. Provider failure occurs
after commit and therefore cannot corrupt business state.

## Operational review

Production logging is structured JSON. Correlation IDs are accepted only in a
bounded safe format or generated by the API, returned to clients, and included
in GraphQL timing and outbox records. Secret-key redaction has focused tests.
Health and readiness have separate semantics and tests.

## Follow-ups

- Extract the polling processor into `apps/worker` when independent scaling or
  deploy isolation is justified.
- Add an S3-compatible object-storage adapter and a separately reviewed data
  migration when production storage requirements are selected.
